## What each file was hiding

1) ledger_conflict_repair_postgres.rs — #[ignore] hid a REAL failure.
   With --ignored the test failed in 0.10s:
     JournalRepair { repaired: false, ..., reason: "durable journal unavailable" }
   Root cause (NOT a code bug): DbLedgerStore::load_events refuses to hand out the
   journal unless AccountingRepo::position_ledger_coverage_complete() is true, and
   that probe is deployment-wide. The shared gate database carried 14 closed
   positions with no ledger backing, so the repair CORRECTLY refused. The test had
   no way to say so: it asserted 'repaired' and printed only 'durable journal
   unavailable', which reads like a broken connection.
   Fix: the test now asserts the coverage precondition itself, with a message that
   names the real cause; it is no longer #[ignore]d, it is env-gated.

2) trusted_proxy_client_ip.rs, accounting_production_retry_postgres.rs — ignored
   only for convenience; both pass against a real database.

3) live_billing_contract.rs (5), live_custody_contract.rs (5), live_stripe_mock.rs (4),
   vault_live_transit.rs (4) — every one of these ALREADY self-skipped: each test
   returns early when its env is absent. The #[ignore] was therefore redundant AND
   harmful: it meant the refusal assertions (NOT_RUN / EXTERNAL_REQUIRED / no local
   fallback / no hardcoded success / no key leak) never ran on any ordinary run.

4) crates/server/src/billing/{paddle,stripe}_adapter.rs + provider_registry.rs — the
   three ignored unit tests asserted 'LIVE_BILLING=1 and a key are set', i.e. they
   checked the environment, not the product. Rewritten to assert the actual gate:
   live requires the opt-in AND a key; a reachable key WITHOUT the opt-in must still
   refuse checkout and name LIVE_BILLING in the refusal.
