# Git history rewrite — secret removal (2026-11-09)

Reason: a REAL Solana keypair (64-byte secret array) was committed in the initial commit at
`work/artifacts/staking_suite-keypair.json`, and a local `config.toml` (gitignored, but tracked
by accident) sat in 3 commits. Both are gone from every commit now.

## What was found (measured, not assumed)

- Secret-material scan over ALL 3,793 blobs of all 61 commits: private-key headers, AKIA*, sk_live_*,
  whsec_*, bot tokens, 64-hex 0x keys and keypair JSON arrays.
- Findings were all TEST FIXTURES (AKIAIOSFODNN7EXAMPLE, 123456789:AAFake.../AAHdq...,
  repeated 0x1111.../0xbbbb... keys, dummy PEM headers) — except exactly one real key:
  `work/artifacts/staking_suite-keypair.json` in commits 3a97f18 (added) and e622faa (removed).
  Its base58 address was derived (88 chars) purely to prove uniqueness — it appeared in 0 other blobs,
  so the leak is exactly that one file, and that file is NOT in the current tree or the packaging
  (`verify-delivery.sh` hygiene rule `*keypair*.json` passes, 0 hits in FILE-LIST.txt).
- `config.toml` blobs: no ACTIVE secret values (the whole `[secrets]` block was commented out;
  the only live value was the public `rpc_url`, no path, no query, no userinfo).
  It was excluded from packaging by the hygiene rule `/config.toml` + `!config.toml.example` in
  .gitignore — so no packaging leak existed; only the git history did.

## What was done

- `git filter-branch --index-filter` over `--all` in a mirror clone, removing by path:
  `work/artifacts/staking_suite-keypair.json`, `:/config.toml`, `:/work/app-run/config.toml`.
  (`git filter-repo` is not installed and the sandbox is offline; filter-branch with an
  `--index-filter` and no `git add` gives the same path-removal result. --prune-empty dropped
  nothing that mattered: 61 commits in, 61 out.)
- Old refs (`refs/original/`), reflogs and stale `refs/remotes` were deleted, then
  `git gc --prune=now`: the pre-rewrite objects are unlinked, not merely unreferenced.

## Verification after

- `git log --all -- '*staking_suite-keypair.json'` → 0 commits; `git log --all -- ':/config.toml'` → 0.
- Full-history rescan of every reachable blob (64,239,100 bytes scanned) → 0 hits for the key array.
- HEAD tree delta vs pre-rewrite HEAD: exactly 1 entry (`config.toml` removed); the other 1,799
  blobs are byte-identical, so no code, evidence or doc content changed.
- The 660 uncommitted working-tree changes were preserved (no stash, no commit created): the
  rewrite ran in a mirror clone and only the branch refs were moved back.
- `verify-delivery.sh` 14 PASS / 0 FAIL, `make gates` 0, `git diff --check` clean.

## Residual (stated, not hidden)

- No remote is configured in this sandbox, so no force-push was possible or performed; the old
  history was never published from here. If a remote copy exists elsewhere it still contains both
  files and must be force-pushed/deleted from that side.
- ANY copy of the old history taken before this rewrite is still a leak; only the key's own
  revocation/rotation makes it harmless. Rotate that keypair before reusing it.
