PostgreSQL dedup expiry source review, 2026-11-09.
DedupRepo mark/exists ignore expires_at until cleanup deletes the row. Zero TTL yields NULL (no expiry). cleanup_expired uses database now() and is invoked by run_maintenance. The L1 bounded set has no TTL in mark, so a remembered key can outlast its L2 entry. This is source analysis, not a runtime scheduling guarantee.
