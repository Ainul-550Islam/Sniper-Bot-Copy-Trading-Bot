# Platform fee wiring — initial source audit, 2026-11-09

Status: OPEN. Source presence/grep audit only, not exhaustive call-path verification or live integration proof.

- `crates/module-copy/src/mirror.rs`, `exit.rs`, and `tenant_executor.rs` exist. No references to `compute_fee`, `build_fee_transfer_ix`, `apply_jupiter_fee`, `PlatformFeeCharge`, or `platform_revenue_posting` in these files. Buy/sell fee collection, tenant fee assessment/posting, retry idempotency and skip journaling remain unimplemented/unverified for the requested paths.
- `crates/module-copy/tests/copy_platform_fee.rs` does not exist.
- `crates/module-polymarket/src/builder.rs` exists as parsing/encoding; its module documentation itself says V2 eip712/venue wiring is a follow-up. `orders.rs`, `pipeline.rs` and `position_orders.rs` reference builder_code, but that does not establish signed-wire attribution for every requested route. Verify strategy/copy/position/Telegram with signed order tests; do not mark complete.
- `crates/module-polymarket/src/tenant_executor.rs` and `reconcile.rs` exist; source search found no PlatformFeeCharge or platform_revenue_posting references. Expected builder revenue versus actual fill/payout reconciliation remains open.
- `crates/core/src/billing/platform_fee.rs` exists; PlatformFeeCharge and posting helpers exist, FeeSurface is absent. `crates/core/tests/platform_fee_surfaces.rs` does not exist.
- `crates/server/src/telegram_trade_port.rs` exists; no fee-transfer/Jupiter fee helper or platform revenue posting references. `crates/server/tests/telegram_fee_wiring.rs` does not exist.
- `solana-kit/src/fee_transfer.rs`: `apply_jupiter_fee` calls `compute_fee(request.amount, cfg)`, describing amount as lamports. On a mint-to-SOL sell `request.amount` is base-token raw units, not lamports. Do not wire this blindly: define sell notional/dust behavior and valid fee account mint using Jupiter's current official integration semantics before using it for money-moving orders. Invalid vault currently silently causes helper to return unchanged request although FeeSkipReason has no invalid-vault variant.
- CLOB official docs accessed 2026-11-09: https://docs.polymarket.com/programs/builders/fees says CLOB V2 signed builder code is bytes32, builder fee is notional times configured maker/taker rate and is additive to market platform fee; accrue on matched fills, daily payout subject to minimum. https://docs.polymarket.com/v2-migration says V2 replaces legacy HMAC builder headers with order builderCode. This does not prove this repository's wire implementation or revenue has been received.
- The actively running workspace test predated this audit, and its result is not yet available. Do not change money paths or invent accounting postings before policy, asset-unit, confirmation, durable idempotency and journal transaction semantics are resolved and covered by tests.

## Follow-up, 2026-11-09
- Copy direct pump-curve buy and sell now prepare atomic native SOL fee instructions and emit prepared/skip audit; invalid nonempty vault with charge fails closed. This is not proof of actual chain collection, durable audit delivery, global tenant policy, Jupiter routes, retry or revenue accounting.
- Jupiter feeAccount now goes on POST /swap rather than quote query and build_swap passes the request fee account through. Official Jupiter docs require an initialized token account for input/output mint; passing a key is not proof of token account validity. Source: https://dev.jup.ag/docs/swap/add-fees-to-swap accessed 2026-11-09. Jupiter sell raw-token vs SOL dust/notional mismatch still open.

## Further follow-up, 2026-11-09
- Copy Jupiter buy/sell and Telegram dispatch now construct Jupiter fee-bearing quote requests; sell dust decision uses initial SOL output quote, not token raw units. The configured Jupiter fee account is checked on RPC for SPL-token owner, initialized WSOL mint. Outgoing swap requests carry feeAccount; requested fee rate and amount are validated in the quote response. Configuration now has a distinct `platform_fee.jupiter_fee_account` from `platform_fee.vault` to avoid treating a token account as native SOL vault. Provider re-quote can shift notional; fee journal remains an audit event (not guaranteed durable) and accounting/reconciliation/actual receipt remain OPEN. No live Jupiter integration proven.
- Telegram offline test `telegram_fee_wiring.rs` checks request preparation only, NOT command/HTTP mock, actual fee leg, revenue ledger, idempotency or live chain. `cargo check -p sniper-suite` passed before separate config account change; final combined tests pending.
- Official Jupiter docs accessed 2026-11-09 https://dev.jup.ag/docs/swap/add-fees-to-swap: feeAccount must be an initialized token account for an eligible pair mint and is sent to /swap. https://dev.jup.ag/api-reference/swap/quote: ExactIn quote output is after fee. The project now explicitly restricts its fee account to WSOL.
