## Verification chain (run after download, in order)

```bash
# 1. checksums — every byte is as shipped
cd buyer-release && sha256sum -c checksums/SHA256SUMS

# 2. structure + version coherence
tests/release/buyer_parity.sh

# 3. source parity with the canonical tree (byte-exact)
scripts/compare-canonical-to-buyer-source.sh

# 4. full release integrity (parity + manifest + contamination + version)
scripts/verify-release-integrity.sh

# 5. manifest currency (counts match the tree)
tests/release/manifest_current.sh

# 6. claim governance + forensic gates
tests/release/marketing_claims.sh
tests/forensics/sql-pattern-regression.sh
tests/business/business-matrix-completeness.sh
```

## What the package does NOT contain (honest exclusions)

* **No secrets, credentials, or keypairs** — verified by the
  contamination scan in `scripts/verify-release-integrity.sh`.
* **No build artifacts** — no `target/`, no `node_modules/`, no
  compiled binaries; the buyer builds from source
  (`docs/BUYER-REPRODUCTION-GUIDE.md`).
* **No live accounts** — no exchange keys, no Stripe/Paddle accounts,
  no Vault/KMS credentials (none exist in the canonical tree either).
* **No final staking program keypair** — the program id is the
  documented pre-deployment placeholder by design; the buyer generates
  the final keypair (see docs/STAKING-PROGRAM-ID-VALIDATION.md).
